News Detection

Dar es Salaam A project by Nathan Kagoro English and Kiswahili

Sixteen outlets, a dozen feeds, two languages, and one small team to read them all before nine

News Detection was a tool that did the reading. A watch-list of names and phrases went in. A digest of the headlines that mentioned them came out.

The problem. A small team needed to know, every morning, whether anyone in the regional press had written about the subjects it cared about. That meant national dailies, broadcasters, the Swahili services of international stations, a busy forum and a list of social accounts. Nobody has the hours to open them all, and the day somebody skips is the day the story runs.

The idea. Let a script make the rounds. It visits each source, collects the newest items, pulls out the title, the author and a summary, and checks the text against the watch-list. Anything that matches goes into one file. The team reads a short list, not the whole newsstand.

This page. The original was written for a private brief, so its real watch-list and results are not shown. To explain the work, the page uses a made-up brief: a conservation charity following coverage of reefs, mangroves and coastal fishing.

The route a story takes

Five steps, run in order, once per source. Nothing clever happens until step four.

  1. Sources

    A plain text list of outlets and accounts. Adding one is a new line, not new code.

  2. Fetch

    Open each front page, find the links that look like articles, and download the newest few.

  3. Extract

    From each page keep four things: title, author, summary, and the visible text.

  4. Match

    Compare the text with every term on the watch-list. This is the step that decides whether the tool is useful.

  5. Digest

    Write the matches to a spreadsheet file, one row per story, with the terms that were found.

    Where it was pointed

    Five kinds of source, each with its own habits.

    • National dailies

      English and Swahili newspapers. Plenty of text and usable page metadata, but every one lays out its site differently.

    • Broadcasters

      Television and radio stations. Their sites carry short write-ups of bulletins, often with no author named.

    • Swahili international services

      The Kiswahili desks of overseas broadcasters. Clean markup, regional coverage, and a different vocabulary from the dailies.

    • Forums

      Long discussion threads where a story often surfaces before the papers have it. Noisy, informal, and written in a mix of both languages.

    • Social accounts

      A list of named accounts and communities. The hardest to read automatically, for reasons given below.

    Corrections and clarifications

    What the first version got wrong, and what each mistake taught.

    Every site is built differently

    The first version had a separate scraper for each outlet, sixteen near copies that each looked for that site's own class names. When a site was redesigned its scraper returned nothing, and said nothing. The cleaned version uses one extractor that reads the preview metadata nearly every news page publishes, and falls back to the first heading and paragraph.

    Social platforms closed their doors

    The social half relied on an unofficial library that read public posts without an account. That route has since been closed. Anything built on an unofficial door stops the day the door is locked, so social sources need an official interface or a licensed feed, and a budget line to go with it.

    A capital letter hid whole names

    The scrapers turned the page text into lower case, then looked for each term exactly as it was typed. A term with a capital letter, which is to say most names of people and places, could never be found.

    looked for Kilwa in kilwa fishers vote…now: Kilwa, KILWA and kilwa all count

    Short words hide inside long ones

    The test was "does this text contain these letters", so a short term fired inside any longer word that happened to contain it. In Swahili the same trap catches kasa, turtle, inside mikasa, incidents.

    found eel in steel prices risenow: only eel as a word of its own

    One subject, two spellings

    A reader knows that mangrove and mikoko are the same story. The first watch-list did not, so half the coverage of any subject depended on someone remembering to type both. A line in the list can now hold every spelling of one term, and the digest reports them under one name.

    Some mistakes need a reader

    Tuna is a fish in English and "we have" in Swahili. No rule about letters can tell them apart, which is why the board above keeps one false alarm however you set it. A digest is a first sift for a person, not a replacement for one.

    Wanted, for a production run

    What this would need before anyone relied on it.

    • Feeds before pages

      Read each outlet's news feed or sitemap where one exists. Scrape pages only as a last resort, and only where the site's rules allow it.

    • A memory

      A record of what has already been reported, so the same story is not flagged every morning for a week.

    • A pulse check

      An alert when a source that normally yields stories returns none. Silence from a broken scraper looks exactly like a quiet news day.

    • A timetable

      A scheduled run that finishes before the team starts work, with the digest sent by email and not left in a folder.

    • Permission

      Official access for social sources, and a check of each site's robots file and terms before it joins the list.

    • A second opinion

      A way for a reader to mark a match as wrong, so the watch-list improves, and context around each match so they can judge it at a glance.
